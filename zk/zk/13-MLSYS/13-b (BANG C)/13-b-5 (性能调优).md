# 性能调优

性能调优的核心目标是提高程序对 MLU 计算单元和访存部件的利用率。整体可以分为两个方向：

- **计算效率最大化**：提高计算并行度，减少计算量，并用更快的等价操作替换慢操作；
- **IO 效率最大化**：减少访存量，提高带宽利用率，并尽可能让访存与计算并行。

## 性能调优的总体原则与流程

### 阿姆达尔定律

阿姆达尔定律（Amdahl's Law）描述固定问题规模下，并行化能够获得的加速比：

![阿姆达尔定律](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/math/7f0d3e95b1496b90f65d24515fc0ac77e4ed664d.png)

```text
S = 1 / (1 - P + P / N)
```

- `P`：程序中可并行部分的比例，取值范围为 `[0, 1]`；
- `1 - P`：程序中串行部分的比例；
- `N`：并行处理节点数量；
- `S`：整个程序相对于串行程序的加速比。

典型情况：

- 当 `P = 1` 时，程序完全并行，`S = N`；
- 当 `P = 0` 时，程序完全串行，`S = 1`；
- 当 `N → ∞` 时，加速比上限为：

![阿姆达尔定律的加速比上限](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/math/48a957a38b5ab0892a63c481ad4410816c64bd1d.png)

```text
S = 1 / (1 - P)
```

例如，并行代码占比 `P = 0.8` 时，即使并行节点无限增加，程序的最大加速比也只有 `5`。

> [!NOTE]
> 单纯增加 MLU Core 或其他并行处理资源无法突破串行部分设置的上限。要取得更高加速比，需要先减少串行部分，提高可并行代码的比例。

### 古斯塔夫森定律

古斯塔夫森定律（Gustafson's Law）从扩展问题规模的角度描述并行系统的加速能力：

![古斯塔夫森定律](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/math/6e7f25e4796e832a592ebed5211602fe86ccdc81.png)

```text
S = N - F(N - 1)
```

- `F`：程序中串行部分的比例，取值范围为 `[0, 1]`；
- `1 - F`：程序中可并行部分的比例；
- `N`：并行处理节点数量；
- `S`：整个程序相对于串行程序的加速比。

当串行比例 `F` 接近 `0` 时，加速比近似与并行节点数量成正比。也就是说，在程序具有足够高并行度的前提下，增加处理器核数能够继续提升可处理的问题规模和整体性能。

### 两条定律的侧重点

| 定律 | 前提 | 主要结论 |
| --- | --- | --- |
| 阿姆达尔定律 | 问题规模固定 | 串行部分决定加速比上限 |
| 古斯塔夫森定律 | 随处理资源扩大问题规模 | 并行比例足够高时，增加处理节点仍然有效 |

两条定律共同说明：并行硬件只有在程序能够提供足够并行任务时才能被有效利用，性能调优首先要提高程序的并行度。

### 性能调优基本原则

在问题规模和硬件参数固定的条件下，提高程序并行度是最重要的优化手段。针对 MLU 的并行能力，可以从两个方向入手：

1. 提高计算任务之间以及计算内部的并行度；
2. 提高计算与 IO 之间的并行度，隐藏数据搬运延迟。

> [!NOTE]
> 性能优化结果与具体硬件相关。在某一款 MLU 上性能最优的实现，迁移到另一款 MLU 后未必仍然最优，需要重新测量和调整。

### 性能调优基本流程

1. **建立性能基准**：以第一份运行正确的代码为基础，记录稳定、可复现的运行时间；
2. **识别性能瓶颈**：判断当前主要受计算能力限制，还是受 IO 和访存限制；
3. **等价变换**：在保证结果正确的前提下修改算法或实现，消除或降低当前瓶颈；
4. **回归验证**：验证结果正确性并重新测量性能，再进入下一轮分析与优化。

```text
正确实现 → 建立基准 → 定位瓶颈 → 等价优化 → 正确性/性能回归
                         ↑                         │
                         └──────── 持续迭代 ───────┘
```

每一轮优化都应优先处理当前最大的性能瓶颈。已经不是主要瓶颈的部分，即使继续优化，对整体运行时间的影响也会受到阿姆达尔定律限制。

## 计算效率最大化

计算效率最大化是指优化计算指令，提高各类硬件运算器的使用率并降低计算耗时。常用方法分为计算并行、减少计算量和等效替代三类。

### 计算并行

MLU 异构计算系统支持七个层次的并行：

1. 服务器级并行；
2. 板卡级并行；
3. 芯片级并行；
4. Cluster 级并行；
5. MLU Core 级并行；
6. 指令级并行；
7. 数据级并行。

计算并行优化的过程，本质上是将算法映射到合适并行层次的过程：

- 服务器级、板卡级并行主要面向训练和大规模推理任务，通常通过 CNCL 通信库和 CNRT 运行时库实现；
- 芯片级、Cluster 级和 MLU Core 级并行由任务拆分、任务规模和任务类型决定；
- 指令级并行通过合理安排 IO、Move、Compute 和 Scalar 流中的指令实现；
- 数据级并行通过 BANG C 向量、张量计算原语实现。

### 减少计算量

从源头减少计算量通常比对相同计算做底层微调更有效。常用方法包括：

- 优化算法，降低计算复杂度；
- 删除无意义的加 `0`、乘 `1` 等操作；
- 使用宏或编译期常量替代运行时常量表达式；
- 对不随输入变化的数据进行预计算。

对于与输入无关的常量，可以在 CPU 侧提前计算，再将结果传入 MLU GDRAM，避免 MLU 重复执行相同计算。

```cpp
// 不推荐：每次在 MLU 上重复计算固定常量
result = input * compute_constant();

// 推荐：CPU 预先计算后，将 constant 作为 Kernel 参数或 GDRAM 数据传入
result = input * constant;
```

### 等效替代

等效替代是使用语义相同、执行速度更快的操作替换慢操作。例如对整数进行 8 倍乘法时：

```cpp
int result_a = value * 8;
int result_b = value << 3;
```

两者结果等价，但移位操作通常具有更好的性能。

> [!NOTE]
> 等效替代必须保证数据类型、溢出规则、精度和边界行为一致。浮点运算不能仅凭代数形式相同就假设结果完全一致。

## IO 效率最大化

IO 效率最大化是指优化访存指令和数据布局，提高访存部件利用率，降低数据搬运耗时，并尽可能实现访存与计算并行。

主要有三类方法：

### 减少访存量

- 避免重复读取相同数据；
- 尽量在 NRAM、WRAM 或 SRAM 中复用已经搬入的数据；
- 合并能够一次完成的搬运操作；
- 只搬运计算真正需要的数据，避免无效区域；
- 在内存容量允许时，用局部缓存减少 GDRAM 往返访问。

### 计算与访存并行

- 将数据分块，在计算当前数据块的同时预取下一数据块；
- 利用不同指令流水线，使 IO、Move 与 Compute 指令重叠执行；
- 通过异步内存拷贝和多个 Queue，让 Host/Device 拷贝与 Kernel 执行重叠；
- 在存在数据依赖的位置进行必要同步，避免过度同步破坏并行性。

```text
时间 →

串行：  搬运 block 0 │ 计算 block 0 │ 搬运 block 1 │ 计算 block 1

并行：  搬运 block 0 │ 搬运 block 1 │ 搬运 block 2
                    │ 计算 block 0 │ 计算 block 1 │ 计算 block 2
```

### 提升带宽利用率

- 使用连续、对齐且粒度合适的内存访问；
- 减少离散访存和过小的数据搬运；
- 根据数据布局合理设置二维、三维拷贝的 pitch；
- Host 与 Device 异步拷贝时优先使用页锁定 Host 内存；
- 根据目标硬件的存储层次、带宽和容量选择数据放置位置。

> [!NOTE]
> IO 优化和计算优化应结合性能数据进行。计算单元等待数据时应优先优化访存；访存带宽尚未成为瓶颈时，继续减少搬运可能无法显著改善整体性能。

## 计算效率最优化

### 使用向量接口优化性能

BANG C 向量接口会把一条操作映射到 MLU 的向量或张量计算单元。只要数据可以连续组织，就应优先用向量接口替代标量循环。

#### 向量相加

标量写法需要逐元素执行：

```cpp
for (int i = 0; i < CHANNELS; ++i) {
  dst_nram[i] = src0_nram[i] + src1_nram[i];
}
```

向量写法只需一次调用：

```cpp
__bang_add(dst_nram, src0_nram, src1_nram, CHANNELS);
```

#### ReLU 激活

```cpp
// 标量实现
for (int i = 0; i < CHANNELS; ++i) {
  dst_nram[i] = src_nram[i] > 0 ? src_nram[i] : 0;
}

// 向量实现
__bang_active_relu(dst_nram, src_nram, CHANNELS);
```

#### 对位最大值

```cpp
// 标量实现
for (int i = 0; i < LEN; ++i) {
  dst[i] = src0[i] > src1[i] ? src0[i] : src1[i];
}

// 向量实现
__bang_maxequal(dst, src0, src1, LEN);
```

求对位最小值时可使用对应的向量接口，思路相同。

#### 向量 split

将一个向量的偶数位和奇数位拆成两个向量时，标量实现需要逐元素取数；向量实现可以先构造掩码，再用 `__bang_collect` 收集有效元素：

```cpp
for (int i = 0; i < LEN / 2; ++i) {
  even[i] = src[2 * i];
  odd[i]  = src[2 * i + 1];
}

// mask_even = {1, 0, 1, 0, ...}
// mask_odd  = {0, 1, 0, 1, ...}
__bang_collect(even, src, mask_even, LEN);
__bang_collect(odd,  src, mask_odd,  LEN);
```

#### 矩阵乘法

矩阵乘法的定义为：

![矩阵乘法定义](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/math/a7900df6b0322f8aba4b34894061c490f72e45f7.png)

标量三重循环不能充分利用 MLU 的矩阵计算单元：

```cpp
for (int m = 0; m < M; ++m) {
  for (int n = 0; n < N; ++n) {
    for (int k = 0; k < K; ++k) {
      C[m * N + n] += A[m * K + k] * B[k * N + n];
    }
  }
}
```

应将左矩阵按行优先放入 NRAM、右矩阵按列优先放入 WRAM，输出放入 NRAM，再调用矩阵乘接口：

```cpp
__nram__ half left[M * K];
__wram__ half right[K * N];
__nram__ float output[M * N];

__memcpy(left,  left_gdram,  M * K * sizeof(half), GDRAM2NRAM);
__memcpy(right, right_gdram, K * N * sizeof(half), GDRAM2WRAM);
__bang_matmul(output, left, right, M, K, N);
__memcpy(output_gdram, output, M * N * sizeof(float), NRAM2GDRAM);
```

部分矩阵乘接口还可在乘加过程中累加已有矩阵：

![矩阵乘加](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/math/89caf427874ec274d1aa93d29e562906bf24e867.png)

> [!NOTE]
> 矩阵尺寸、数据类型、内存布局和对齐要求必须满足具体 `__bang_matmul` 接口约束；不能只把标量循环机械替换成接口调用。

#### 置零操作

在需要把 NRAM 向量清零时，`__bang_write_zero` 通常比通用的 `__nramset` 更快：

```cpp
__bang_write_zero(dst_nram, data_num);
```

### 使用融合操作优化性能

融合接口把多个操作合并为一条高效指令，减少中间结果、指令数和访存。常用接口包括：

- `__bang_fusion`：执行可配置的融合计算；
- `__bang_fcmpfilter`：比较并筛选数据；
- `__bang_fabsmax`：求绝对值最大值；
- `__bang_fabsmin`：求绝对值最小值。

选择融合接口前，应确认融合语义、数据类型、舍入方式和原实现一致。

### 使用查表功能实现并行间接访问

标量间接访问会按索引逐个读表：

```cpp
for (int i = 0; i < LEN; ++i) {
  dst[i] = table[index[i]];
}
```

索引和查找表满足接口约束时，可以用向量查表并行完成：

```cpp
__bang_lut_s32(dst, table, index, LEN);  // 32 位查表
__bang_lut_s16(dst, table, index, LEN);  // 16 位查表
```

### 合理使用核内同步和核间同步接口

同步范围越大，等待的指令流或计算核越多，代价也越高。因此应使用能够保证正确性的最小同步范围。

- 核内同步优先使用针对具体流水的接口，如 `__sync_copy_nram_to_dram`、`__sync_copy_sram_to_nram`、`__sync_compute`；
- 只有确实需要同步核内全部指令流时才使用 `__mlvm_sync`；
- 核间同步优先使用较小范围的 `__sync_cluster`；
- 只有跨更大范围存在依赖时，才使用 `__sync_all_ipus`、`__sync_all_mpus` 或 `__sync_all`。

> [!NOTE]
> 缩小同步范围的前提是依赖关系分析正确。遗漏必要同步会造成读写竞争，得到不稳定或错误结果。

### 选择合适的接口实现核内指令流并行

功能相近的接口可能由不同指令流执行。例如：

- `__bang_write_value` 使用 Compute 流；
- `__memset_nram` 使用 Move 流。

如果 Compute 流正在执行大量计算，可以将置值操作安排到 Move 流；反之亦然。接口选择不仅取决于单条指令速度，还要考虑它能否与周围指令并行。

### 利用多核并行计算优化性能

多核并行分为数据并行、模型并行和混合并行。数据可以均匀切分时，最直接的方法是按 `taskId` 给每个 MLU Core 分配不同区间。

单核版本：

```cpp
__mlu_global__ void divKernel(float *dst, const float *src0,
                              const float *src1) {
  const int LEN = 65536;
  // 单个 Core 处理全部数据
  for (int i = 0; i < LEN; ++i) dst[i] = src0[i] / src1[i];
}
```

`Union8` 多核版本：

```cpp
#define LEN 65536
#define CORE_NUM 32
#define PER_CORE_LEN (LEN / CORE_NUM)

__mlu_global__ void divKernel(float *dst, const float *src0,
                              const float *src1) {
  int offset = taskId * PER_CORE_LEN;
  for (int i = 0; i < PER_CORE_LEN; ++i) {
    dst[offset + i] = src0[offset + i] / src1[offset + i];
  }
}
```

### 增加核间并行度

核间同步之前应尽量安排相互独立的工作。若 Core 1 一开始就等待 `__sync_all`，它会在 Core 0 工作期间空闲；可以把 Core 1 不依赖 Core 0 的搬运和计算移到同步之前：

```cpp
if (coreId == 0) {
  // Core 0 的前置计算
  __bang_add(...);
} else if (coreId == 1) {
  // 与 Core 0 无依赖，可提前执行
  __memcpy(...);
  __bang_max(...);
}
__sync_all();
// 此处再使用跨核产生的数据
```

### 使用 Cluster 间流水

不同 Cluster 可以承担流水线的不同阶段。例如 Cluster 0 负责乘法，结果经 SRAM 传递给 Cluster 1，Cluster 1 再完成加法：

```cpp
if (clusterId == 0) {
  __bang_mul(mul_nram, x_nram, y_nram, LEN);
  __memcpy_async(shared_sram, mul_nram,
                 LEN * sizeof(float), NRAM2SRAM);
}
__sync_all();
if (clusterId == 1) {
  __memcpy(add_nram, shared_sram,
           LEN * sizeof(float), SRAM2NRAM);
  __bang_add(out_nram, add_nram, bias_nram, LEN);
  __memcpy(out_gdram, out_nram,
           LEN * sizeof(float), NRAM2GDRAM);
}
```

这种拆分适合阶段间数据量可控、计算量足以覆盖同步与跨层搬运开销的任务。

## 编译器常用技巧

### 常数预处理

对不随运行时输入变化的表达式，应尽量在编译期或 Host 侧提前计算。这样既减少 MLU 指令，也给编译器更多常量传播和指令折叠机会。

### 使用位运算

当 `N` 是 2 的幂时：

![N 是 2 的幂](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/math/883109d77859b0fefc46ade008431cd807933c35.png)

可以用按位与替代取模：

```cpp
// N = 2^n
int r0 = i % N;
int r1 = i & (N - 1);
```

此变换只在 `N` 为 2 的幂且整数符号、负数行为符合预期时成立。

### 编译暗示

#### `__builtin_assume_aligned`

告诉编译器指针满足指定对齐：

```cpp
void *aligned = __builtin_assume_aligned(ptr, 32, 8);
```

上例表示 `ptr - 8` 按 32 字节对齐。该提示不会在运行时检查对齐，承诺错误会产生未定义行为。

#### `__builtin_assume`

告诉编译器某个条件恒为真，便于删除分支或加强优化：

```cpp
bool in_nram = __is_nram(ptr);
__builtin_assume(in_nram);
```

`__builtin_assume` 不生成运行时检查，实参也不应包含副作用。直接把可能被视为有副作用的调用写进参数，编译器可能忽略该提示，因此应先保存布尔结果。

#### `__builtin_unreachable`

标记控制流不可能到达的位置：

```cpp
switch (mode) {
  case 0: run0(); break;
  case 1: run1(); break;
  default: __builtin_unreachable();
}
```

只有在该路径确实不可能执行时才能使用，否则属于未定义行为。

#### `__restrict__`

`__restrict__` 向编译器承诺多个指针不会指向重叠区域，从而消除别名分析障碍：

```cpp
__mlu_global__ void add(float *__restrict__ dst,
                        const float *__restrict__ a,
                        const float *__restrict__ b) {
  // dst、a、b 的有效访问区间不能重叠
}
```

#### 标量加载函数

已知地址空间时，使用对应的显式加载函数可帮助编译器生成更合适的访问指令：

```cpp
float a = __load_gdram(gdram_ptr);
float b = __load_ldram(ldram_ptr);
float c = __load_nram(nram_ptr);
float d = __load_sram(sram_ptr);
```

#### 标量存储函数

标量存储同样应使用与目标地址空间匹配的接口，明确数据写往 GDRAM、LDRAM、NRAM 或 SRAM，避免通用指针带来的额外判断和保守代码生成。

#### `__builtin_expect`

该接口向编译器提示分支更可能出现的结果：

```cpp
long __builtin_expect(long exp, long c);

#define likely(x)   __builtin_expect(!!(x), 1)
#define unlikely(x) __builtin_expect(!!(x), 0)

if (likely(size == aligned_size)) {
  fast_path();
} else {
  tail_path();
}
```

它只影响代码布局和分支优化，不改变表达式结果；应根据真实运行分布设置，而不是凭感觉滥用。

## 访存优化

### 减少访存数据量

#### 片上驻留

高频复用的数据应尽量留在 NRAM、WRAM 或 SRAM，避免反复访问 GDRAM。卷积 Filter 通常优先放在 WRAM；放不下时可以先按 Core 拆分，仍放不下时再把分片放入各 Cluster 的 SRAM 并轮转使用。

![Filter 在不同 Cluster 间轮转](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/filtercircle.png)

#### 计算换访存

如果某个中间量重新计算的代价明显低于读写它的代价，可以不保存中间量，而在使用位置重新计算。该方法只适用于访存是主要瓶颈的场景；计算受限时反而可能变慢。

### 计算和访存并行

#### 重排代码

在加法后接卷积的例子中，可以先搬运加法输入并启动加法，同时异步把卷积 Filter 搬到 WRAM，最后只在真正使用 Filter 前同步：

```cpp
__memcpy(add0_nram, add0_gdram, bytes, GDRAM2NRAM);
__memcpy(add1_nram, add1_gdram, bytes, GDRAM2NRAM);

__bang_add(add_out_nram, add0_nram, add1_nram, len);
__memcpy_async(filter_wram, filter_gdram,
               filter_bytes, GDRAM2WRAM);

__sync_io();
__bang_conv(output_nram, add_out_nram, filter_wram, ...);
```

#### 软流水

软流水将数据分块，通过多组片上缓冲区重叠不同迭代的访存和计算。

##### 三级流水

三级流水包含加载 `L`、计算 `C` 和存储 `S` 三个阶段，并用两组 NRAM 缓冲区做 Ping-Pong：

![三级流水](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/pingpong.png)

```cpp
if (n > 0) { L(0); __sync_io(); }
if (n > 1) { C(0); L(1); __sync_io_move_compute(); }

for (int i = 0; i < n - 2; ++i) {
  S(i % 2);
  C((i + 1) % 2);
  L(i % 2);
  __sync_io_move_compute();
}

if (n > 1) S(n % 2);
if (n > 0) {
  C((n - 1) % 2);
  __sync_compute();
  S((n - 1) % 2);
}
```

也可以把预热、稳态和排空统一到一个带边界判断的循环中：

```cpp
for (int i = 0; i < n + 2; ++i) {
  if (i >= 2) S((i - 2) % 2);
  if (i >= 1 && i < n + 1) C((i - 1) % 2);
  if (i < n) L(i % 2);
  __sync_io_move_compute();
}
```

##### 四级流水

四级流水引入 Memory Core 和 SRAM，可以把加载或存储再拆成一级。典型阶段为：

```text
GDRAM --L(Memory Core)--> SRAM --M(MLU Core)--> NRAM
      --C(MLU Core)--> NRAM --S--> GDRAM
```

![四级流水](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/pingpong4.png)

实现时应分别为 SRAM 和 NRAM 设置 Ping-Pong 缓冲，并在 GDRAM→SRAM、SRAM→NRAM、计算、写回四个阶段之间使用最小范围同步。

##### 五级流水

五级流水同时拆分加载和存储：

```text
GDRAM --L--> SRAM --M1--> NRAM --C--> NRAM --M2--> SRAM --S--> GDRAM
```

![五级流水](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/pingpong5.png)

五级流水提供更多重叠机会，但需要更多片上空间和同步。阶段耗时不均衡、数据量较小时，增加级数不一定更快。

### 提升带宽利用率

#### 数据对齐

| 地址空间 | 地址对齐 | 数据量对齐 |
| --- | ---: | ---: |
| NRAM | 16 B | 128 B |
| SRAM | 16 B | 128 B |
| WRAM | 64 B | 128 B |
| GDRAM | 512 B | 512 B |
| LDRAM | 512 B | 512 B |

无法满足 512 B 数据量对齐时，应依次优先考虑 256 B、128 B、64 B 等较大且规则的粒度。

#### 张量化访存

张量化访存遵循三个原则：

1. 用一次向量搬运替代逐标量访问；
2. 把连续的小块合并成一次较大的 1D 搬运；
3. 对规则的跨步区域使用 2D 搬运，不要在循环中反复发起小拷贝。

```cpp
// 连续区域：合并为一次搬运
__memcpy(dst, src, total_bytes, GDRAM2NRAM);

// 跨步区域：使用二维搬运
__memcpy(dst, src, width,
         NRAM2NRAM, dst_stride, src_stride, repeat);
```

#### 阶梯式访存

广播数据时可按 `GDRAM → SRAM → NRAM/WRAM` 搬运，让同一 Cluster 内多个 Core 复用 SRAM；汇聚结果时反向按 `NRAM/WRAM → SRAM → GDRAM` 搬运。这样可以减少多个 Core 对 GDRAM 的重复访问。

## Kernel 级别的性能优化

Kernel 级优化主要有三种方法：Kernel 融合、多队列并行和多队列流水。

### Kernel 融合

相邻 Kernel 之间存在可复用的中间结果时，可以把它们融合，省去中间数据写回 GDRAM、再次读入和额外的 Kernel 启动。

```cpp
// 融合前：scale 和 relu 分开，中间结果写回 GDRAM
scaleKernel<<<...>>>(tmp, input, scale);
reluKernel<<<...>>>(output, tmp);

// 融合后：中间结果保留在 NRAM
__mlu_global__ void scaleReluKernel(float *output,
                                    const float *input,
                                    float scale) {
  __nram__ float buf[LEN];
  __memcpy(buf, input, LEN * sizeof(float), GDRAM2NRAM);
  __bang_mul_scalar(buf, buf, scale, LEN);
  __bang_active_relu(buf, buf, LEN);
  __memcpy(output, buf, LEN * sizeof(float), NRAM2GDRAM);
}
```

融合会增加单个 Kernel 的资源占用，需要权衡 NRAM/WRAM 容量、并行度和代码复杂度。

### 多队列并行

以具有 4 个 Cluster 的 MLU270 为例，可以创建两个 Queue，每个 Queue 启动只占用部分 Cluster 的 `Union2` Kernel，使两组任务并行执行：

```cpp
cnrtQueue_t queue0, queue1;
cnrtQueueCreate(&queue0);
cnrtQueueCreate(&queue1);

cnrtMemcpyAsync(dev0, host0, bytes, queue0, CNRT_MEM_TRANS_DIR_HOST2DEV);
kernel<<<dim0, cnrtFuncTypeUnion2, queue0>>>(dev0);
cnrtMemcpyAsync(host0, dev0, bytes, queue0, CNRT_MEM_TRANS_DIR_DEV2HOST);

cnrtMemcpyAsync(dev1, host1, bytes, queue1, CNRT_MEM_TRANS_DIR_HOST2DEV);
kernel<<<dim1, cnrtFuncTypeUnion2, queue1>>>(dev1);
cnrtMemcpyAsync(host1, dev1, bytes, queue1, CNRT_MEM_TRANS_DIR_DEV2HOST);
```

前提是单个 Kernel 没有占满设备资源，否则多 Queue 也无法形成真正并行。

### 多队列流水

可以分别用三个 Queue 承担 H2D、Kernel 和 D2H，并以 Notifier 表达跨 Queue 依赖，让多个 Batch 形成流水：

![多队列流水](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/cnrtPipeline.png)

```text
Queue 0：H2D(batch 0) ─ H2D(batch 1) ─ H2D(batch 2)
Queue 1：              Kernel(0) ───── Kernel(1) ───── Kernel(2)
Queue 2：                           D2H(0) ─────── D2H(1) ─────── D2H(2)
```

## 使用 Notifier 提高设备利用率

如果 Host 每轮都同步 Queue、处理输出，再提交下一轮任务，Host 处理期间设备会空闲：

![Notifier 流水](https://www.cambricon.com/docs/sdk_1.15.0/cntoolkit_3.7.2/programming_guide_1.7.0/_images/notifierpipeline.png)

可以使用两组输入/输出缓冲和两个 Notifier 做 Ping-Pong。Notifier 记录在 D2H 之后，Host 只等待即将复用的那组缓冲，处理当前结果的同时，设备继续执行另一组任务：

```cpp
for (int i = 0; i < batch_num; ++i) {
  int slot = i & 1;
  cnrtNotifierWait(notifier[slot]);
  process_host_output(slot);

  cnrtMemcpyAsync(dev_in[slot], host_in[slot], bytes,
                  queue, CNRT_MEM_TRANS_DIR_HOST2DEV);
  kernel<<<dim, type, queue>>>(dev_out[slot], dev_in[slot]);
  cnrtMemcpyAsync(host_out[slot], dev_out[slot], bytes,
                  queue, CNRT_MEM_TRANS_DIR_DEV2HOST);
  cnrtPlaceNotifier(notifier[slot], queue);
}
```

Notifier 仅用于依赖同步、不需要计时时，可关闭计时功能以降低开销：

```cpp
cnrtNotifierCreateWithFlags(&notifier,
                            CNRT_NOTIFIER_DISABLE_TIMING_ALL);
```

## 向量加法性能调优案例

示例路径为 `samples/BANG/3_Performance/vectoradd`，构建方式为：

```bash
cd your_sample_path/BANG
./build.sh --mlu370
cd build/test
```

测试环境为 MLU370-X4（8 个 Cluster，每个 Cluster 4 个 MLU Core）、CNToolkit 3.4.0 和驱动 5.10.4。案例重点观察 `policyFunc` 与 Device 代码。

调优结果如下：

| 优化技术 | MLU 硬件执行时间（μs） | MLU 访存效率 | MLU 计算效率 |
| --- | ---: | ---: | ---: |
| 单核标量 | 8464968 | 0.000046 | 0.000001 |
| 多核标量 | 270891 | 0.001442 | 0.000036 |
| 单核向量 | 4566 | 0.085551 | 0.002139 |
| 单核向量三级流水 | 4330 | 0.090214 | 0.002255 |
| 多核向量 | 450 | 0.868056 | 0.021701 |
| 多核向量三级流水 | 449 | 0.871931 | 0.021798 |
| 多核向量四级流水 | 447 | 0.873881 | 0.021847 |
| 多核向量五级流水 | 444 | 0.879786 | 0.021995 |

### 单核标量版本

基线版本使用一个 MLU Core，用标量循环处理两个含 1000 万个 `float` 的向量：

```cpp
for (int i = 0; i < data_num; ++i) {
  output[i] = input0[i] + input1[i];
}
```

执行时间为 `8464968 μs`，计算与访存效率都极低。

### 多核标量版本

`policyFunc` 根据每个 Cluster 的 Core 数和 Cluster 总数设置 `Union1` 网格，Device 端用 `taskId`/`taskDim` 切分数据：

```cpp
int per_task = data_num / taskDim;
int begin = taskId * per_task;
int end = taskId == taskDim - 1 ? data_num : begin + per_task;
for (int i = begin; i < end; ++i) {
  output[i] = input0[i] + input1[i];
}
```

时间降到 `270891 μs`，比基线减少约 97%。

> [!NOTE]
> 优化技巧 1：尽量使用设备上可用的全部并行计算资源。

### 单核向量化版本

单核向量版本把数据按 NRAM 容量分块，并把分块长度按 `NFU_ALIGN_SIZE = 128 B` 对齐：

```cpp
__memcpy(src0_nram, input0 + offset, bytes, GDRAM2NRAM);
__memcpy(src1_nram, input1 + offset, bytes, GDRAM2NRAM);
__bang_add(dst_nram, src0_nram, src1_nram, count);
__memcpy(output + offset, dst_nram, bytes, NRAM2GDRAM);
```

执行时间大幅降到 `4566 μs`。

> [!NOTE]
> 优化技巧 2：使用向量接口替代标量计算。  
> 优化技巧 3：让向量访存处理连续的数据块。  
> 优化技巧 4：满足地址和数据量对齐要求。

### 单核向量三级流水版本

使用两组 NRAM 缓冲，把输入加载、`__bang_add` 和输出写回重叠，时间进一步降至 `4330 μs`，只改善约 5%。这表明单核版本已经主要受 IO 限制。

> [!NOTE]
> 优化技巧 5：用软流水重叠访存和计算，但收益取决于当前瓶颈。

### 多核向量版本

将向量化分块同时分配给全部 MLU Core 后，执行时间降到 `450 μs`，访存效率升至 `0.868056`。这一步结合了多核并行和数据级并行，是整个案例中收益最大的阶段之一。

### 多核向量三级流水版本

在多核向量版本上增加三级流水后，时间为 `449 μs`，几乎没有变化。此时瓶颈已经接近设备访存上限，计算与访存重叠无法继续带来明显收益。

### 多核向量四级流水版本

引入 Memory Core 和 SRAM 后，时间为 `447 μs`。四级流水增加了 GDRAM→SRAM→NRAM 的层次，SRAM 中转也会产生开销，因此收益很小。

### 多核向量五级流水版本

五级流水进一步把写回也拆成 NRAM→SRAM→GDRAM，时间为 `444 μs`，仍只有轻微改善。连续发射同一类型指令还可能导致相应指令队列反压。

> [!NOTE]
> 优化技巧 6：不要长时间连续发射同一种指令；应结合依赖关系交错安排不同指令流，让硬件流水保持并行。

该案例说明，优化应按“多核并行 → 向量化 → 连续且对齐的访存 → 计算与访存重叠”的顺序逐步验证。流水级数越多并不代表性能越好，最终仍取决于真实瓶颈和硬件资源利用率。
